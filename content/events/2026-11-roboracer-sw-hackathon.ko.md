## 상세 안내

### 1. 대회 개요

- 목적: 자율주행 레이싱카(F1TENTH)의 소프트웨어를 직접 구현해 보며 자율주행 알고리즘 역량을 기르고, 참가자들이 함께 겨루고 배우며 교류하는 기회를 만드는 것입니다. 자동 채점과 AI 튜터의 한국어 피드백으로 처음 도전하는 분도 단계적으로 따라올 수 있도록 설계했습니다.

- 방식: 온라인 해커톤입니다. 모든 팀이 같은 시각에 시작하고, 정해진 기간 안에 각자 코드를 GitHub 저장소에 commit 하면 자동으로 채점됩니다.

- 참가 대상: 누구나 신청할 수 있습니다. IEEE ITSS 회원이 아니어도 됩니다.

- IEEE ITSS 가입은 참가 조건이 아니라 권유입니다. 가입 방법이 궁금하시면 아래 문의처로 문의해 주십시오.

- 팀 구성: 1명에서 3명까지입니다. 혼자 참가하셔도 됩니다. 한 사람은 한 팀에만 참여할 수 있습니다.

- 시상: 순위에 따라 시상합니다. 수상 팀에게는 IEEE ITSS 한국 지회 명의의 증서를 수여합니다. 시상식은 충북대학교에서 11월 25일(수) 오전 11시경 열릴 예정이며, 수상 팀의 참석 방법은 따로 안내합니다. 참가 증명서는 마감 전에 push 하여 채점 결과를 받은 팀의 모든 팀원에게 발급하며, 11월 25일까지 신청서의 email 로 보내 드립니다.

### 3. 과제

- Lab 02: 자동 긴급 제동(AEB) 안전 노드. 라이다 거리값으로 충돌까지 남은 시간(TTC)을 계산해, 위험할 때 차를 멈추는 노드를 구현합니다. 자동 채점 11개 항목을 모두 통과하는 것이 순위에 오르기 위한 조건입니다.

- Lab 04: Follow the Gap. 장애물이 있는 복도를 라이다만으로 충돌 없이 끝까지 주행하는 노드를 구현합니다. 시뮬레이션 주행 3개 항목(명령 발행, 끝까지 완주, 무충돌)을 모두 통과하면 "정상 완주"이고, 순위는 정상 완주한 팀의 완주 시간(랩 타임)으로 정합니다. 그 밖의 검사(코드 구조, 단위, 스타일)는 피드백용이며 자격과 순위에 반영하지 않습니다.

- Lab 04 시뮬레이터 제한 (대회 규칙): 최고 속도 6 m/s, 가속도 4 m/s^2, 조향각 +-24도, 조향 속도 제한. 제한을 넘는 명령은 제한값으로 잘려서 적용되며 감점은 없습니다. 첫 충돌이 일어나면 그 주행은 끝납니다. 이 제한은 안내를 낸 뒤에는 바꾸지 않습니다.

- 과제마다 팀 저장소가 하나씩 만들어집니다. 저장소의 README 에 실행 방법과 제출 방법을 적어 두었습니다.

### 4. 참가 방법

- 1단계: [참가 신청서(Google Form)](https://forms.gle/chtypdJy2w8ALTcC9)를 11월 11일(수) 23:59 까지 제출합니다. 팀 이름, 팀원의 이름, 소속, email, GitHub 계정, 그리고 그 GitHub 계정에 연결된 email 을 적습니다. GitHub 계정이 없으면 미리 만들어 주십시오. 팀 이름은 GitHub 저장소 이름에 쓰이므로 영문 소문자, 숫자, 하이픈(-)만 사용하여 3~30자로 정합니다. 혼자 참가하면 팀 이름을 비워 두어도 됩니다(GitHub 계정 이름으로 정합니다). 제출한 내용을 고치려면 신청 마감 전에 문의해 주십시오.

- 2단계: 신청 마감 후, 신청서에 적은 GitHub 계정으로 organization(itss-korea-roboracer-2026) 초대 메일이 발송됩니다. 11월 15일(일) 23:59 까지 수락해 주십시오. 기한까지 수락하지 않으면 참가를 포기한 것으로 처리합니다. 초대 메일이 보이지 않거나 기한이 지난 경우에는 11월 15일(일)까지 문의하시면 다시 초대해 드립니다.

  초대 메일은 신청서에 적은 email 이 아니라 GitHub 계정에 등록된 email 로 발송되며, 스팸함으로 분류될 수 있습니다. 메일이 보이지 않으면 문의해 주십시오.

- 3단계: 대회 시작 시각에 팀 저장소가 만들어지고, 팀원 모두가 접근할 수 있게 됩니다. 저장소는 비공개이며 팀원과 운영자만 볼 수 있습니다.

- 4단계: 저장소의 main 브랜치에 commit 하면 자동 채점이 실행되고, 결과가 해당 commit 에 점수로 표시됩니다 (Lab 02 는 Score N/11, Lab 04 는 Score N/14). 보통 몇 분 안에 표시됩니다. 횟수 제한 없이 고쳐서 다시 올릴 수 있습니다. 템플릿을 고치지 않고 그대로 올리면 Lab 02 는 Score 6/11, Lab 04 는 Score 6/14 가 나옵니다. 여기서부터 시작합니다.

- 마감 시점의 기록 인정 방식: 마감(11월 23일 23:59) 전에 push 하여 채점 결과가 나온 것 중 가장 좋은 기록을 인정합니다. 저장소별로 따로 집계합니다. Lab 02 는 11개 항목을 모두 통과한 push 가 한 번이라도 있으면 되고, Lab 04 는 정상 완주한 push 중 완주 시간이 가장 짧은 기록을 씁니다. 마감 이후의 push 는 순위에 반영하지 않습니다. 마감 전에 push 한 것은 채점 결과가 마감 이후에 표시되어도 인정하지만, 채점에는 몇 분이 걸리므로 마감 직전에는 여유를 두고 push 해 주십시오. 짧은 간격으로 연속 push 한 경우의 채점은 6절을 참고해 주십시오.

### 5. 순위 산정

- 자격: Lab 02 의 11개 항목을 모두 통과하고 Lab 04 를 정상 완주한 팀만 순위에 오릅니다. 자격에 못 미친 팀도 채점 결과와 튜터 피드백은 받습니다.

- 순위: 자격을 갖춘 팀 가운데 Lab 04 의 완주 시간(랩 타임)이 짧은 순서입니다.

- 같은 기록이면 먼저 push 한 팀이 앞섭니다. GitHub 서버에 기록된 push 시각을 기준으로 합니다. commit 에 적힌 날짜는 참가자 컴퓨터의 시계에 따라 달라질 수 있어 사용하지 않습니다.

### 6. 규칙

- 생성형 AI(LLM), 공개 문서, 오픈소스의 사용은 제한하지 않습니다.

- 다른 팀의 코드를 복사해 제출하는 것과, 마감 전에 자신의 풀이를 공개하는 것은 허용하지 않습니다. 공개 저장소, 블로그, 게시판, 단체 대화방 등에 코드를 올리는 것이 공개에 해당합니다.

- 특정 지도의 좌표나 경로를 코드에 직접 써 넣는 방식(하드코딩)은 허용하지 않습니다. 센서(라이다) 값을 읽고 반응하는 코드여야 합니다. 운영진이 상위 3팀의 코드를 확인한 뒤 순위를 확정합니다.

- 채점 시스템은 모든 참가팀이 함께 씁니다. 같은 저장소에 짧은 간격으로 여러 번 push 하면 중간 push 는 채점되지 않을 수 있고, 가장 최근 push 는 채점됩니다. 짧은 시간에 push 를 과도하게 반복하는 등 채점 시스템에 부하를 주는 행위가 확인되면 해당 팀 저장소의 쓰기 권한을 제한할 수 있습니다.

- 규칙을 어긴 것으로 확인되면 순위에서 제외합니다.

- 이 규칙들에 대한 의견은 참가 신청서의 의견란으로 받습니다. 의견은 대회 시작 전에 검토하며, 규칙이 바뀌면 시작 전에 알려 드립니다.

### 7. AI 튜터

- 채점이 끝나면 AI 튜터가 코드를 읽고 한국어로 피드백을 저장소의 Issues 에 남길 수 있습니다. 피드백은 채점에 실패한 push 와 처음으로 모든 항목을 통과한 push 에 남습니다. 운영 중 조정될 수 있습니다.

- 튜터의 설명은 참고용이며 틀릴 수 있습니다. 점수는 자동 채점 결과로만 정해집니다.

### 8. 개인정보

- 신청서에서 받는 항목은 이름, 소속, email, GitHub 계정, GitHub 계정에 연결된 email 이고, IEEE 회원번호는 선택 항목입니다. 사용 목적은 참가 확인, GitHub 초대, 결과 안내, 시상과 참가 증명서 발급입니다. 응답은 시상식(11월 25일) 후 30일이 지나면(12월 25일경) 삭제하고, 팀 이름과 순위만 남깁니다. 팀 저장소와 제출한 코드도 같은 때에 삭제하며, 삭제 전에 각자 내려받아 보관할 수 있습니다.

- 대회 기간 중 만들어지는 정보(저장소의 코드, 채점 결과, AI 튜터의 피드백, push 시각)도 같은 목적으로 처리하며, AI 튜터의 피드백을 만들기 위해 제출한 코드는 외부 생성형 AI 서비스로 전송됩니다. 수상 팀의 팀 이름과 팀원의 성명과 소속은 지회 채널에 공개될 수 있습니다. 신청서의 개인정보 수집 및 이용 동의 안내를 함께 확인해 주십시오.

- 제출한 코드를 향후 대회 운영 개선, 교육, 연구에 쓰는 것은 신청서의 선택 동의 항목에서 동의한 팀의 코드에 한하며, 신원 정보를 제거한 사본만 최대 3년간 보관합니다. 동의하지 않아도 참가와 순위에는 영향이 없습니다. 위의 삭제 일정은 그대로 적용됩니다.

- GitHub organization 의 구성원 목록(Members)은 같은 organization 구성원끼리 서로 보입니다. 외부에는 공개되지 않으며, 각 팀 저장소의 내용은 다른 팀이 볼 수 없습니다.
